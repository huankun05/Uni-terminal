## 0. 结论速览

| 问题 | 答案 |
|---|---|
| 桌面端做成什么应用？ | **核心是无头 Node 服务。GUI 是有的 —— 在浏览器里，不在窗口里。另加一个零依赖的启动器消除终端窗口。** |

# 1. 桌面端形态

## 1.1 先纠正一个提法：GUI ≠ 有窗口

你担心的是"不做 Electron 就得手改 JSON 配置路径"。**这个担心在 v1 里确实没被回答掉。** 但两种情况都不是必然：

**①「不做 Electron」≠「没有图形界面」**

`/local` 管理台就是一个完整的 GUI：开关、下拉框、目录选择器、二维码、设备管理。只是它渲染在浏览器标签页里，而不是原生窗口里。

**②「要配置」≠「要手改文件」**

真正该问的不是"用什么方式配置路径"，而是 **"为什么需要配置路径"**。答案是：**不该需要。** 详见第 2 章。

丢掉的东西确实有三样，逐条都有解：

| 丢掉什么 | 具体表现 | 解法 |
|---|---|---|
| **服务起来之前没有界面** | 配置坏了 → 服务退出 → 管理台也打不开 → 被锁在外面（**死锁**） | **降级启动**（§2.4）。这是当前代码的真实缺陷，必须修 |
| **桌面存在感** | 没图标、没托盘、看不到它在跑 | L2 启动器 + 可选 L3 托盘（§1.4） |
| **原生能力** | 文件选择对话框、开机自启开关 | 自启走界面一键注册；文件选择用**服务端目录浏览**替代，反而更好用（§2.3） |

## 1.2 为什么仍然否决「窗口型应用」

不是图省事，是三条硬理由：

| 理由 | 说明 |
|---|---|
| **① 服务必须比窗口活得久** | 主窗口应用 = 关窗口就停服务 = 手机失联。而核心场景恰恰是"人在外面，家里电脑上不该有窗口开着"。这就退化成 ZCode 了 |
| **② 桌面 UI 在"你不在电脑前"时价值最低** | 真实管理动作（批准新设备、吊销丢失的手机）都该能在手机上做。桌面台的密集使用集中在**首次配对那五分钟** |
| **③ 打破「零编译」的代价被低估** | 引入 Tauri = 贡献者都要装 Rust 工具链；Electron = 150MB + 一条独立更新链。对一个"一个人长期维护、希望别人也能改"的开源项目，这是主要成本 |

**但 v1 的结论有一个漏洞**：这三条只否定了**窗口型**应用，没有否定**不需要窗口的辅助层**。所以把形态拆成四层。

## 1.3 定案：四层形态

```
L3  托盘（可选）         图标 + 右键菜单：打开控制台 / 复制地址 / 重启 / 退出
                         实现：Windows 用 PowerShell NotifyIcon（零编译，约 60 行）
                         ↑ 通过 HTTP API 调服务，与服务完全解耦

L2  启动器 uni-terminal   隐藏终端窗口 · 打开管理台 · 注册/注销开机自启
                         实现：Node 原生 spawn(detached + stdio:ignore + windowsHide)
                         ↑ 只负责"把 L0 拉起来"，拉起后自己立即退出

L1  浏览器管理台 /local   全部配置的 GUI。桌面密集使用集中在首次配对
                         ↑ 同一个 HTTP 服务，"仅回环可达"解锁管理接口

L0  核心服务（无头）       开机就在跑的 Node 进程
                         ★ 必须独立于任何窗口 —— 这才是否决 Electron 的真正理由
```

**关键设计**：L2 / L3 都是**可选的装饰**。删掉它们，L0 照样跑。这让"应用感"和"零依赖"不必二选一 —— 而 v1 把它们当成互斥的了。

## 1.4 L2 启动器：用 Node 消除终端窗口

Windows 上双击 `.cmd` 会弹一个黑窗口，关掉它就杀掉子进程 —— 这是"不像应用"的根源。两个动作解决：

### 动作 1 · 脱离控制台

服务的子进程用 `spawn(node, args, { detached: true, stdio: 'ignore', windowsHide: true })` 拉起，启动器自己立即退出。效果：

- 黑窗口关掉 → 服务还在跑（已 detach）
- 黑窗口根本不出现（`windowsHide`）

> ⚠️ **实践中容易踩的坑**：`windowsHide` 对 **console 子系统**程序有效，对 GUI 子系统程序无效；且如果父进程本身是 console 而没有正确 detach，Windows Terminal 会接管并为子进程开新标签页。三个参数必须同时给：`detached: true` + `stdio: 'ignore'` + `windowsHide: true`，缺一不可。

### 动作 2 · 一句话命令

```bash
npx uni-terminal start               # 前台（首次安装、调试）
npx uni-terminal start --background  # 后台静默（自启场景，不开浏览器）
npx uni-terminal open                # 只打开管理台
npx uni-terminal status              # 打印配置路径 + 探测结果 + 运行状态
npx uni-terminal install-service     # 注册开机自启（等价于管理台里的按钮）
```

日常使用是**开始菜单快捷方式**（指向一次 `start --background` 后打开浏览器），而不是敲命令。

## 1.5 三个入口

| 入口 | 地址 / 形式 | 什么时候用 |
|---|---|---|
| **① 终端** | `npm start` | 首次安装、排查问题、SSH、无浏览器环境。**配对二维码直接 ASCII 打印** |
| **② 本机管理台** | `http://127.0.0.1:8787/local` | 首次配对、配置 Agent、批准设备、诊断 |
| **③ 手机控制台** | `http://<局域网IP>:8787/m` | 日常使用 |

②③是同一个 HTTP 服务，区别只在访问来源：本机请求才解锁 `/api/local/*`（判定逻辑在 `http/local.ts`，三条件同时成立，fail-closed）。

## 1.6 分发与自启动

分发走 npm 包（`npx uni-terminal`），不做安装包。

自启动用**任务计划程序**，明确不用 Windows 服务 —— 服务跑在 Session 0，与用户桌面会话隔离，会导致：① 拿不到你的 `PATH` → 找不到 `claude`/`codex`/`node`；② 拿不到凭据与环境变量 → API Key、git 凭据全失效。而要驱动的 Agent 恰恰全都需要这些。

```powershell
# 用启动器而不是直接跑服务：为了拿到 windowsHide，登录时不闪黑窗口
$action  = New-ScheduledTaskAction -Execute "node" `
  -Argument "`"$HOME\uni-terminal\packages\server\src\cli.ts`" start --background" `
  -WorkingDirectory "$HOME\uni-terminal"
$trigger = New-ScheduledTaskTrigger -AtLogOn
$set     = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
  -RestartInterval (New-TimeSpan -Minutes 1) -RestartCount 3
Register-ScheduledTask -TaskName "Uni-terminal" -Action $action -Trigger $trigger -Settings $set
```

**这条命令不该让用户手敲。** 它由管理台的一个按钮触发，界面要显示"是否已注册自启"的开关状态。这是"配置也要有 GUI"的一部分。

# 2. 配置体验（v2 新增 —— 这是你提的问题的核心）

## 2.1 重新定义问题

你的原话是"最开始需要去配置这些路径，不太便于用户使用"。回答分两层：

> **第一层：「配路径」这件事本身应该被消灭 —— 路径要被「发现」，而不是被「配置」。**
> **第二层：万一真要配，全部配置项都必须有界面；并且绝不能出现"配置坏了就打不开界面"的死锁。**

而且我们有一个被低估的优势：**目标用户就是"已经在用 AI 编程工具的人"**。Claude Code、Codex、Gemini CLI 全都是 npm 全局安装的，所以这些命令**本来就在他们的 PATH 里** —— 否则他们自己的工作流都跑不起来。

## 2.2 第一层：零配置启动（覆盖 ~95% 的人）

首次启动做一次**环境普查**，用户什么都不做。

### ① Agent 发现 —— 不能只扫 `process.env.PATH`

当前实现（`agents/detect.ts`）只扫进程 PATH，这不够。要补上：

| 来源 | 为什么必要 |
|---|---|
| `process.env.PATH` | 基础。但注意：由任务计划程序启动时，PATH 可能与交互式 shell 不同 |
| **npm 全局前缀** | `%APPDATA%\npm`（Windows）/ `/usr/local/bin`。**Claude Code / Codex / Gemini CLI 都在这里**，而它不一定在服务进程的 PATH 里 |
| **pnpm / bun / volta / nvm / fnm 的 shim 目录** | 各版本管理器各有一套 bin 目录 |
| **常见安装位置** | `%LOCALAPPDATA%\Programs\`、`~/.local/bin`、`/opt/homebrew/bin`、`~/.bun/bin` |
| **`where.exe` / `which` 兜底** | 一次性调用（不是每个 agent 都调），带 `windowsHide` 避免窗口闪现 |
| **Windows 注册表 PATH** | 用户级 + 系统级的原始值，绕过进程环境的污染 |

### ② 工作区默认值 —— 不能用 `process.cwd()`

当前默认是 `process.cwd()`。问题是：从开始菜单快捷方式启动时，cwd 可能是 `C:\Windows\System32`。改为按优先级取：

1. 配置里已有的工作区
2. 启动器传入的 cwd（用户从某个项目目录启动）
3. 用户主目录

首次启动再给几个**智能候选**：扫主目录下常见的代码目录名（`Projects` / `Code` / `Work` / `Desktop` / `Documents`）里带 `.git` 的一级子目录，列出来让用户勾选（也可以一个都不选）。

### ③ 结果落到配置文件，并在横幅打印

```
  发现 3 个可用的 AI 编程工具，已全部启用
    ✓ claude     C:\Users\x\AppData\Roaming\npm\claude.cmd
    ✓ codex      C:\Users\x\AppData\Roaming\npm\codex.cmd
    ✓ qwen       C:\Users\x\AppData\Roaming\npm\qwen.cmd
  未发现（不影响使用）：gemini, cursor-agent, mimo, ...

  工作区        F:\Work\project
  配置文件      C:\Users\x\.uni-terminal\config.json
```

### ④ 语义：探测到的默认全启用，而不是默认全关

这是刻意选择。传统上"安全默认"要求默认关闭，但这里的资源是**你自己机器上、你自己的 Agent**，且访问已被配对 + 设备凭据 + 可吊销保护。默认全关会让每个用户都要做一遍配置 —— 正好是你要避免的。

所以原则是：**默认全开、可关**（关掉某个 = 不想让手机碰它），而不是**默认全关、要开**。

## 2.3 第二层：全部配置项有界面（覆盖剩下那 5%）

**当前缺口：没有配置读写接口。** 配置只在启动时同步读一次，改任何一项都要"手改 JSON + 重启"。这是 v1 的真实漏洞，要补：

| 新增接口 | 用途 |
|---|---|
| `GET /api/local/config` | 读取生效配置 + 文件路径 + 是否有未生效改动 |
| `PATCH /api/local/config` | 局部更新。**能热生效的立即生效，需重启的明确告知** |
| `POST /api/local/agents/rescan` | 重新做环境普查，返回探测结果（不动配置） |
| `POST /api/local/agents/:id/test` | **真的跑一次 `--version`**，返回输出与退出码 |
| `POST /api/local/fs/list?path=` | **仅回环**的目录列举，用于界面内的路径选择器 |
| `GET /api/local/service` | 自启是否已注册 / 实际监听端口 / 运行时长 |

（全部标注 `仅回环`，沿用 `isLocalOrigin` 的三条件判定。）

`/local/settings` 页面结构：

```
┌─ AI 编程工具 ────────────────────────────────────────┐
│  [ 重新扫描 ]                                         │
│  ☑ claude    ...\npm\claude.cmd      可用  [测试] [改路径] │
│  ☑ codex     ...\npm\codex.cmd       可用  [测试] [改路径] │
│  ☐ gemini    未找到                          [手动指定] │
│  ☑ qwen      ...\npm\qwen.cmd        可用  [测试] [改路径] │
├─ 工作区 ──────────────────────────────────────────────┤
│  • 默认工作区   F:\Work\project    ● git    [浏览] [移除] │
│  [ + 添加工作区 ]                                      │
├─ 服务 ────────────────────────────────────────────────┤
│  端口              8787   （被占用时自动顺延；当前实际 8787）│
│  启动时打开管理台    ● 开                              │
│  开机自启            ○ 未注册           [ 一键注册 ]    │
├─ 传输 ────────────────────────────────────────────────┤
│  ● 局域网（默认）   ○ Cloudflare   ○ EasyTier（未配置）  │
│  说明：外网传输在 v1 之后接入，接口已预留               │
└───────────────────────────────────────────────────────┘
```

### 「改路径」怎么选文件？

浏览器不能开原生文件对话框。但有三个替代，加起来**比原生对话框更好用**：

1. **「重新扫描」**（主要手段）—— 95% 的情况点一下就找到了
2. **粘贴路径 + 「测试」** —— 粘贴后立即跑 `--version` 验证，错了立刻知道
3. **界面内目录选择器** —— 服务端有文件系统权限，`/api/local/fs/list` 列目录；前端做成一个**能搜索**的迷你浏览器。原生对话框不能搜索，这个能

补一条：**工作区也要能验证** —— 选完对着它跑一次 `git rev-parse`，能识别出"这是 git 仓库"就标出来。

## 2.4 第三层（最重要）：绝不能被锁在外面

**当前代码有一个真实死锁：**

```
config.ts:104-131   JSON 解析失败 → throw
index.ts:440-449    catch → log.error + process.exit(1)
结果                 服务没起来 → 管理台打不开 → 唯一能修配置的界面不可达
                    用户只能去手改 JSON ← 正好是你担心的情况
```

必须修。四条硬约束：

| 约束 | 实现 |
|---|---|
| **配置坏了也要能启动** | 解析失败 → **备份为 `config.json.bak-<时间戳>`** → 用默认配置启动 → 管理台顶部红色横幅「配置文件有误，已用默认配置启动。恢复备份？」 |
| **端口被占用也要能启动** | 从 `8787` 起顺延找可用端口（默认最多到 8797），横幅与管理台都显示**实际端口**；固定端口的部署可关闭顺延 |
| **数据目录不可写也要能启动** | 降级为**只读诊断模式**：起一个最小 HTTP 服务，只提供 `/local/recover`（诊断信息 + 建议 + 配置路径），不出会话功能 |
| **任何降级都要在界面上可见** | 不能只写日志。管理台顶部常驻「降级运行」徽章 + 原因 + 修复入口 |

这样配置体验就闭环了：**默认不用配 → 要配就有界面 → 配坏了也进得去界面。**

## 2.5 配置文件的定位（重新说清楚）

v1 隐含了一个假设：配置文件是给用户编辑的。**改为：配置文件是应用的持久化层，正常使用中用户永远不需要打开它。**

- 首次启动自动生成，内容来自环境普查
- 全部字段都能通过界面修改
- JSON 不支持注释 → 改为：**`uni-terminal.example.json` 是给人读的文档**，实际配置文件是机器写的
- 高级用户仍可直接编辑（改完重启，或界面上点「重新加载配置」）

# 3. 手机端形态

## 3.1 定案：一个 PWA，三组路由，按路由分割代码

```
/                  着陆分流 —— 极简页，判设备类型后跳转
/pair?id=&c=       扫码落地 —— 手机扫完码到这里
/m  /m/s/:id       手机控制台 ← 主战场
/local /local/*    桌面管理台 ← 只在 127.0.0.1 可达
/inapp             内置浏览器拦截页（微信 / QQ / 部分国产浏览器）
/install           添加到主屏幕引导页
```

**为什么是同一个应用而不是两个**：二维码渲染、事件卡片、状态徽章这些组件两端共用；一套构建、一套部署、一个版本号。但要用 `React.lazy` 做**路由级代码分割**，保证手机端首屏不加载桌面台的管理代码。

## 3.2 信息架构：三屏 + 三段式底部导航

```
┌─────────────────────┐  ┌─────────────────────┐  ┌─────────────────────┐
│  ① 现在             │  │  ② 新建任务         │  │  ③ 设置             │
│                     │  │                     │  │                     │
│  ┌───────────────┐  │  │  选 Agent           │  │  本机地址 / 指纹    │
│  │ ● 正在运行    │  │  │  ┌───┐┌───┐┌───┐   │  │  传输模式           │
│  │ Claude Code   │  │  │  │claude│codex│qwen│ │  │  已配对设备         │
│  │                │  │  │  └───┘└───┘└───┘   │  │  ├ iPhone 15  ⌫     │
│  │ 改 auth 模块的  │  │  │                     │  │  └ iPad       ⌫     │
│  │ 4 个文件        │  │  │  工作目录           │  │                     │
```

## 3.3 首屏设计：状态优先，不是列表优先

**这是手机端最重要的设计判断。**

远控场景里，用户掏出手机的动机按频率排序：

1. **"它跑完了吗？"** —— 最高频
2. **"它卡住了吗？要不要我做什么？"** —— 次高频
3. **"我要开个新任务"** —— 中等
4. "翻上次那个会话的记录" —— 最低

而绝大多数同类产品的首屏是**会话列表**，等于把最高频的第 1、2 问埋进了第 4 类操作里。

所以：

- **首屏顶部永远是「当前状态卡」**：正在跑 → 显示 Agent、当前动作、已完成步骤、待处理事项；空闲 → 显示"空闲中，最近活动 3 分钟前"
- **不自动跳进任何会话**（E1 已定）—— 打开应用先看到全局状态，由你决定进哪个。切后台回来被自动带进某个会话会让人失去位置感
  - 补偿设计：活跃会话卡片**整块可点**，不需要精确点某个小按钮 → 从看到状态到进入详情仍只要一次点击
- **待处理事项（权限请求）用醒目色块顶到最上面** —— 这是唯一"不处理就会一直卡着"的事件类型
- 已结束的会话折叠在下方，默认收起
- 从会话详情返回时**回到列表原来的滚动位置**，不重置到顶部

## 3.4 输入设计：任务下达框 + 上下文快捷应答

手机上打字成本高，所以不做通用聊天框：

- **默认形态**：`任务描述` 多行输入 + 发送。提交后作为一次性 prompt 送进 Agent
- **需要交互时**（Agent 抛出 y/n 或选项）：输入框上方**自动浮出快捷按钮** —— `继续` / `是` / `否` / `停止` / `Ctrl+C`。**点一下就走，不需要打字**
- 高级入口：一个「发送按键」小面板（Esc、Tab、↑↓、Ctrl+C、y、n），给 PTY 模式兜底

## 3.5 核心：事件 → UI 面板映射

这是"不直出终端"的落地点。服务端把事件存进 `events` 表并推给前端，前端按 `type` 分派：

| 事件 type | 渲染组件 | 手机上的具体形态 |
|---|---|---|
| `agent_message`（增量文本） | `StreamText` | 流式文本块，用正文字体而非等宽 |
| `tool_call` / `tool_result` | `ToolCard` | 工具图标 + 一行命令摘要 + 状态点（进行中/成功/失败）+ 可展开输出 |
| `tool_call` 携带 diff | `DiffView` | 内嵌 diff：红绿行 + 行号，**默认只展开前 N 行** |
| `plan` | `PlanList` | 任务清单 + 勾选态，作为"它还差几步"的可视化 |
| `request_permission` | `PermissionSheet` | **底部操作单**，含 diff/命令预览 + 允许/拒绝。原生手感 |
| `terminal_output` | `TerminalPane` | **可折叠面板，默认收起**，展开后是 xterm.js（懒加载） |
| `current_mode_update` | `ModeBadge` | 顶部模式徽章（如 plan / act） |
| `error` | `ErrorCard` | 醒目卡片 + 重试按钮 |
| `session_end` | `StatusPill` | 状态改为"已结束" + 退出码 |

## 3.6 双通道在前端如何统一

项目的核心是双通道（ACP 结构化 / PTY 原始字节），前端要**按会话的驱动模式给不同默认视图**：

| 驱动模式 | 事件来源 | 默认视图 | 终端面板 |
|---|---|---|---|
| **ACP** | 结构化事件 | 卡片面板（上表） | 隐藏（无原始字节流） |
| **PTY** | 原始字节流 | **终端摘要**：剥掉 ANSI 转义，取尾部若干行渲染成"当前状态"文本块 | **保留**，是唯一完整视图 |

PTY 模式下没有结构化事件，所以要有 `lib/ansi.ts` 做**转义序列剥离 + 尾部截取**，让手机上至少能看到"它现在在打什么字"。这是 v1 的必经形态（PTY 先跑通，ACP 后接）。

## 3.7 PWA 化清单

| 项 | 内容 | 坑 |
|---|---|---|
| `manifest.webmanifest` | `name` / `short_name` / `display: standalone` / `theme_color` / `background_color` | 服务端 MIME 已支持 `.webmanifest` |
| 图标 | 192 / 512 / **maskable 512** | maskable 不提供的话，Android 主屏图标会被裁掉一圈 |
| **screenshots** | 2 张（手机竖屏优先） | **提供后 Android 安装弹窗从"小横条"升级为"App Store 风格大弹窗"**，成本仅两张图 |

| 安装引导 | Chromium：捕获 `beforeinstallprompt` → 显眼按钮；iOS：图文引导页 | `prompt()` **只能调一次**，拒绝后有约 3 个月冷却 → **只在配对成功后弹** |
| 微信 / QQ 拦截 | UA 检测 → 全屏遮罩页 | 见 §3.8 |

## 3.8 内置浏览器拦截（国内最高优先级）

微信内置浏览器（Android X5 / iOS WKWebView）**不支持添加到主屏幕、不支持 Service Worker、不支持 WebAuthn**。在这个环境里方案是**功能性残废**，不是体验降级。

而国内用户的默认动作就是**用微信扫码**。所以：

1. **UA 检测**（`MicroMessenger` / `QQ/` / `Weibo` 等）→ 直接渲染拦截页
2. **不给"继续访问"按钮** —— 放行了也是个不能用的页面，给了按钮只会让用户困惑
3. **分平台跳出步骤** + 箭头动画指向右上角 `···`
4. **「复制链接」按钮**兜底（手动粘到系统浏览器）
5. **二维码旁边就写明「请用相机扫码，不要用微信扫」** —— 把问题挡在扫码之前，比扫码后再拦更有效

**WebSocket `/ws`**（30s 心跳，凭 `seq` 重放）

| 方向 | type | 说明 |
|---|---|---|
| S→C | `hello` | 连接建立，带 `local` / `deviceId` / `heartbeatMs` |
| S→C | `event` | 会话事件（`session` / `seq` / `type` / `payload`） |
| S→C | `sessions` | 会话列表快照 |
| S→C | `subscribed` | 订阅确认，带 `from`（最后发出的 seq） |
| S→C | `revoked` | **凭据被吊销，必须立刻清理本地状态** |
| S→C | `error` | 错误 |
| C→S | `sub` / `unsub` | 订阅 / 退订（`from` = 已知最大 seq） |
| C→S | `input` / `interrupt` / `resize` | 会话控制 |
| C→S | `sessions` | 请求列表快照 |

**重连协议（前端核心逻辑）**：断开 → 指数退避重连 → 重连成功后对每个订阅发 `sub` 并带上**本地记录的最后一个 seq** → 服务端从该 seq 之后补齐。断线期间事件不丢、不重复渲染。这是手机端体验底线（切后台、切网是常态）。

|---|---|---|
| **明文 HTTP** | 局域网内无 TLS，同网段可嗅探 | v1 接受，启动横幅已明确告警；外网走隧道时由隧道提供 HTTPS |
| **PTY 模式 UI 弱** | 没有结构化事件，只能给终端摘要 | v1 必经形态。ACP 接入后结构化事件面板才是主体验 |
| **首次配对需在电脑前** | 物理约束，无法绕过 | 反正只需要一次（L2 凭据 180 天滑动续期） |
| **iOS 添加到主屏需手动** | 浏览器限制，无 `beforeinstallprompt` | 用图文引导优化转化，不追求消灭这一步 |
| **`prompt()` 一次机会** | 拒绝后约 3 个月冷却 | **只在配对成功后弹**，不在首次进页面就弹 |
| **E2E 加密未做** | 走隧道时对 CF 可见明文 | 配对阶段已登记手机公钥，加 E2E 不需要重新配对（架构已留口） |
| **明文 HTTP 下 WebCrypto 不可用** | 手机经局域网 HTTP 配对时 crypto.subtle 为 undefined（安全上下文限制） | 已修：公钥退化为随机标识（服务端本就只存不用）；E2E 上线时经已建立的凭据通道下发公钥轮换接口，无需重新配对（真机验证 2026-09-12 发现） |
| **配置改动需重启**（部分项） | 端口、数据目录无法热改 | 界面明确标注「需重启」，并提供一键重启；热生效项（Agent 开关、工作区）立即生效 |
| **托盘仅 Windows** | L3 用 PowerShell 实现 | 一期接受。跨平台托盘等有人提需求再上 Tauri tray-only |

# 7. 已定决策

| # | 问题 | 决定 | 说明 |
|---|---|---|---|
| **E1** | 手机端首屏默认行为 | **停在状态总览页，不自动跳转** | 打开应用先看全局，由用户决定进哪个。补偿：活跃会话卡整块可点，进详情仍只需一次点击 |
| **E2** | 一期是否引入桌面壳 | **不引入窗口型应用；引入 L2 启动器（Node 原生）** | v1 的"不做壳"过于绝对 —— 它只该否定"窗口型应用"，不该否定"消除终端窗口的辅助层"。L2 零新依赖，L3 托盘可选 |
| **E3** | 手机端是否保留真实终端视图 | **保留但默认收起，懒加载** | PTY 模式下它是唯一完整视图；ACP 模式下它不存在。懒加载保证不影响首屏 |
| **E4** | 配色与视觉风格 | **暗色优先 + 玻璃质感**，保留浅色切换 | 建立一套 CSS 变量设计令牌统一两端；暗色为默认 |
| **E5** | Agent 默认启用语义 | **探测到的默认全启用，而非默认全关** | 资源是用户自己的 Agent，且已被配对 + 凭据 + 可吊销保护。默认全关会让每个用户都要配置一遍 —— 正是要避免的 |
| **E6** | 配置故障处理 | **任何配置问题都以降级启动告终，绝不以退出告终** | 备份 + 默认值 + 界面内修复。修复目标是消灭"手改 JSON"这条路径 |
| **E7** | 桌面壳的范围 | **L2 启动器一期做；L3 托盘 Windows 优先、可延后** | 启动器解决"黑窗口 + 不像应用"，成本极低；托盘是锦上添花 |

# 8. 设计令牌（视觉基线）

用一层语义变量隔离主题，两端共用，切主题只换变量值：

| 令牌 | 用途 |
|---|---|
| `--bg-base` / `--bg-surface` / `--bg-elevated` | 页面底色 / 卡片 / 浮层（三档亮度递进） |
| `--border-subtle` | 分隔与描边 |
| `--text-primary` / `--text-secondary` / `--text-tertiary` | 三级文字对比 |
| `--accent` | 单一强调色：主按钮、进行中 |
| `--state-running` / `--state-waiting` / `--state-done` | 状态三色 |
| `--diff-add` / `--diff-del` | 仅 diff 使用 |

三条约束：

1. **玻璃质感只用在浮层**（底部操作单、配对弹窗、顶部渐隐条）—— 大面积半透明会拖累滚动性能，手机上尤其明显。列表和卡片用实色
2. **状态色只有三个** —— 不要给每种事件类型分配颜色，否则首屏会变成调色盘
3. **diff 的红绿不并入状态色体系** —— 避免"这个绿是成功还是新增"的歧义
