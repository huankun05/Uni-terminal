## 1. 目标

### 一句话

**做一个自托管的统一 AI 编程 Agent 控制台：手机浏览器扫码即用，一个界面驱动电脑上所有 AI 编程工具（Claude Code / Codex / Gemini CLI 等 22 个），不装 App、不经第三方中继、Windows 优先。**

### 目标达成的判定标准（最小闭环）

以下三件事全部跑通，即项目成立；缺任何一件都不算：

1. **配对一次，长期免扫码** —— 电脑上出二维码，手机相机扫码 → 电脑上人工点「允许」→ 此后打开网址即登录（180 天滑动续期，iOS 上不丢登录态）。
2. **手机上完整驱动一个真实任务** —— 新建会话（Claude Code）→ 看到它在做什么 → 发输入 → **处理权限请求让它继续** → 任务正常结束。
3. **全程约束成立** —— 服务端零编译（`npm install` 即可跑）、手机不装 App、流量不经任何第三方服务器。

### 明确的非目标（一期不做，防止范围蔓延）

- ❌ 窗口型桌面应用（Electron/Tauri）—— 只做 L2 启动器 + 可选 L3 托盘
- ❌ 外网传输（Cloudflare Tunnel / EasyTier）—— 接口已预留，一期只做 `lan`
- ❌ E2E 载荷加密 —— 配对流程已登记手机公钥，后加不需要重新配对
- ❌ ACP 全量打通 —— 先 PTY + 单 Agent（Claude Code）打样闭环，ACP 结构化事件随后接入
- ❌ 多用户 / 团队权限 —— 定位自用 + 开源，单管理员 + 多设备

## 2. 怎么实现（方案骨架，均已定稿）

```
┌─ 手机（PWA，React 19 + zustand + xterm 懒加载）
│    /pair 扫码落地 · /m 状态卡首屏 + 事件卡片面板 · /local 桌面管理台（同应用路由分割）
│
├─ 传输：lan 局域网直连（v1）─ 适配器接口可插拔 → cloudflare / easytier
│
├─ 服务端（Node 22.18+ 原生 TS 直跑，Hono + ws，node:sqlite，零编译）
│    四层凭据安全（L1 配对码 5min / L2 设备 Cookie 180d / L3 会话 15min）
│    配对 = 扫码只发起 + 人工授权（RFC 8628 三层限流）· Ed25519 服务指纹防冒充
│    会话运行时 + 事件持久化 + seq 重放（断线不丢）
│
└─ Agent 驱动（双通道）
     PTY（node-pty，所有 Agent 通用）← v1 先跑通
     ACP（acpx/runtime，结构化事件 → 卡片面板）← 随后接入
```

| 决策域 | 定稿 | 出处 |
|---|---|---|
| 统一接入 | acpx（MIT，22 Agent 目录）+ PTY 兜底 | 调研报告 02 |
| 桌面形态 | 无头服务 L0 + 浏览器管理台 L1 + 启动器 L2 + 托盘 L3 | 实施文档 01 §1 |
| 配置体验 | 发现而非配置（默认全开可关）+ 全界面化 + 降级启动绝不退出 | 实施文档 01 §2 |
| 凭据 | 三层模型，长寿命只给身份且走 httpOnly Cookie（iOS ITP 硬约束） | 设计文档 01 |
| 配对 | 二维码只是 pairId，授权必须人工点击；三层限流 + 30s 轮换 | 设计文档 02 |
| 常驻 | 任务计划程序（非 Windows 服务，保住用户 PATH 与凭据） | 设计文档 02 |
| 手机端 | 状态卡首屏（非会话列表）· 权限请求置顶 · 快捷应答 · 微信拦截 | 实施文档 01 §3 |

## 3. 本轮调研更新（2026-09-11 第六轮）

### ✅ 3.1 acpx 选型确认成立

acpx 官方站点（acpx.sh）与 OpenClaw 文档确认：MIT 许可的 headless ACP 客户端，内置 Claude / Codex / Gemini / Cursor / Copilot / Droid / OpenCode 等 adapter，另有 `--agent` 接任意自定义 ACP server。**统一接入层的技术前提没有变化，且生态在活跃迭代。**

### 🔧 3.2 node-pty 编译风险已解决（本轮最重要的产出）

原方案标记的风险：`node-pty` 1.1.0 在 Windows + Node 22 上若无预编译包会回退 node-gyp，用户需要 VS Build Tools —— 直接违背「零编译」承诺。

**实测结论**：`@lydell/node-pty`（只分发预编译二进制、**从不调用 node-gyp**）在本机（Windows 11 + Node 22.22）`npm install` **786ms 完成、无任何编译**，真实 PTY spawn（`cmd.exe /c echo`）输出与退出码均正常。

**动作**：把 `node-pty` 依赖替换为 `@lydell/node-pty`（已列入 M0-0.8）。`driver.ts` 的 pipe 降级后端保留作最后兜底。

### ⚔️ 3.3 竞品动态：Claude Code 官方已出 Remote Control

Anthropic 官方文档确认已上线 **Remote Control**（`claude remote-control` → 扫码 → 手机上继续/批准会话，走 claude.ai/code 与 Claude 移动 App）。Happy（23.7k★）是同模式的第三方先行者。

**这是市场验证，不是威胁**：每家工具都在做自己的私有远控闭环（ZCode、Claude Remote Control、未来 Codex 也会有）——「管 5 个工具要配 5 套远控」的问题被官方方案加重而非解决。本项目「ACP 统一接入 + 纯浏览器 + 自托管」的差异化反而更清晰。需要做的一件小事：README 的论述更新为「各家（包括官方）各做一个，所以更需要统一层」。

## 4. 实施路线（顺序即优先级）

> 每个任务的验收标准已在《实施文档 01》§5，此处只列骨架与顺序依据。

| 里程碑 | 内容 | 为什么在这个位置 |
|---|---|---|
| **M0 服务端配置层加固** ✅（2026-09-12 完成，83 项断言通过） | 降级启动 · 端口顺延 · Agent 发现扩展 · 环境普查 · 6 个配置接口 · L2 启动器 · @lydell/node-pty 替换 | 已实现并测试覆盖；0.7 的「双击快捷方式无黑窗口」真机验收留待 M5 |
| **M1 前端骨架 + 通信层** | Vite/React 工程 · HTTP 封装 · WS 心跳 + seq 重放 · 事件 store | 先跑通数据不做美化；重放是手机端体验底线 |
| **M2 桌面配对台 + 配置界面** | 二维码轮换 · 待批准弹窗 · 设备吊销 · Agent/工作区全程界面配置 | ★ **最小闭环里程碑**：M2 完成 = 配对真实可用 |
| **M3 手机控制台** | 状态卡首屏 · 事件面板 · 权限操作单 · 快捷应答 · 折叠终端 | 让它「真的好用」 |
| **M4 PWA 化 + 国内适配** | manifest/SW · 三平台安装引导 · **微信拦截页** | 微信拦截优先级等同核心链路（国内用户默认微信扫码） |
| **M5 真机验收** | iOS 登录态存活 · 后台回来事件不丢 · 真跑一个 Claude Code 任务 | 以 §1 的三条判定标准逐条验收 |

一期完成后的方向（顺序）：ACP 结构化事件接入 → Cloudflare Tunnel → E2E 加密（配对已留口，无需重配）→ Passkey → 跨平台托盘。
