# 调查报告 03 — 移动端会话呈现优化

*2026-09-12 · 起因：真机反馈「菜单选项被合并」「历史视图内容混乱」「按键不好用」，要求调查同类产品并给出方案。*

---

## 1. 问题与根因

| 现象 | 根因 | 定性 |
|---|---|---|
| 菜单选项被合并（"1 Yes2. Yes,anddon'task…"） | Claude Code 的 TUI 会**重绘**菜单：把多个选项写进同一行（光标移动指令被 strip 后粘连）；窄终端（44 列）还会把长选项折行 | 启发式解析的边界缺陷，**可修**（已修，见 §3.1） |
| 历史视图混乱（thinking*8…、居中错位、状态栏碎片） | Claude Code 跑在终端**备用缓冲区**（alt-buffer）：全屏重绘、无滚动历史。剥掉 ANSI 后，**多次重绘的帧碎片混在一起**——这不是解析 bug，是 strip 路径的理论上限 | strip 路径天花板，启发式只能"尽力可读"（已修，§3.2） |
| 终端视图不能下滑看历史 | alt-buffer **天生没有回滚缓冲**，任何终端模拟器都一样 | 只能靠其他视图承载历史（已做：文本视图改名「历史」，承载完整净化文本） |

**核心认知：只要 Claude Code 以交互 TUI 方式跑在 PTY 里，终端字节流就没有可靠的结构。** 一切"从字节流猜结构"的努力都有天花板。

## 2. 同类产品怎么做（调查结论）

| 产品 | 做法 |
|---|---|
| **Happy**（23.7k★，最直接竞品） | **不用终端**。CLI 包装器以 `claude --print --input-format stream-json --output-format stream-json` 拉起 Claude Code，把 **NDJSON 结构化事件**（助手文本、工具调用、结果）推给手机 App 渲染成卡片流。手机输入也以 JSON 写回 stdin |
| **Claude Code 官方**（Remote Control / SDK） | 官方支持的编程接入方式就是这个：`claude -p --input-format stream-json --output-format stream-json --verbose`（`--replay-user-messages` 回显用户消息）。各语言 SDK（Elixir/Rust/Python…）全部基于它 |
| **Omnara / vibe-kanban 等** | 同类结构化思路：各自解析或包装，无一例外**不直接把 TUI 字节流当 UI** |

**结论：行业共识 = 用 Claude Code 的 stream-json 双向通道拿结构化事件，终端只留给真正需要看 TUI 的人。** 我们的 xterm 终端视图保留（它是 TUI 的忠实视图），但"手机友好的主视图"应该建立在 stream-json 上。

官方文档：<https://code.claude.com/docs/en/cli-reference>

## 3. 修复与方案

### 3.1 已实施（本轮）

1. **菜单解析重写**：不再按行匹配，改为在尾部以「❯ / Do you want / proceed?」最后一次出现为锚做**全局编号匹配**——重绘合并进同一行的选项能正确拆分（实测合并/折行/正常三态全过），标签截断 48 字符宁短勿混，重绘重复按首现保留。
2. **历史净化 `humanizeTranscript()`**：TUI 居中缩进去除、`thinking*8…` 旋转残骸剔除、状态栏行（esc to… / Cooked for… / shift+tab…）整行丢弃、重绘重复行去重。历史视图与会话摘要改用净化版。**如实标注**：这是"尽力可读"，忠实还原只有终端视图能做。
3. 按键面板补全（←/→/PgUp/PgDn/Home/End）。

### 3.2 中期方案（建议下一个功能里程碑）：`claude-json` 驱动模式

给 Claude Code 增加独立驱动：不进 PTY，而是

```
spawn: claude -p --input-format stream-json --output-format stream-json --verbose
发任务: stdin 写 {"type":"user","message":{"role":"user","content":[{"type":"text","text":…}]}}
收事件: stdout 逐行 JSON → assistant 文本 / tool_use（含完整命令与参数）/ tool_result
```

收益：**命令、文本、结果天然分离** → 手机端渲染成真正的卡片流（这正是用户要的"哪些是执行的命令、哪些是纯文本、哪些要选择"），权限请求也有结构化形态（配合 `--permission-prompt-tool` stdio MCP）。

已知风险（调查所得，均有应对）：
- 事件 schema 官方文档不足（[issue #24594](https://github.com/anthropics/claude-code/issues/24594)）→ 以实测 + SDK 源码为准，解析层做成容错；
- `--resume` 与 stream-json 组合有挂起案例（[issue #53584](https://github.com/anthropics/claude-code/issues/53584)）→ 一期不做 resume，会话重启即新建；
- 仅覆盖 Claude Code → 其他 Agent 继续 PTY 兜底，**不影响 ACP 长期路线**（acpx 覆盖 22 家时统一切换）。

### 3.3 长期

ACP（acpx/runtime）作为所有 Agent 的统一结构化通道，claude-json 模式届时成为其子集或被替代。

## 4. 建议顺序

1. ✅ 本轮启发式修复（已上线）
2. **claude-json 驱动 + 卡片流**（下一个功能里程碑，用户价值最大）
3. ACP 统一接入
